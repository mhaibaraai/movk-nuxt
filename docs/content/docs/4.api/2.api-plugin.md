## 介绍

`$api` 是通过 Nuxt 插件注入的全局 `$fetch` 实例，内置完整的拦截器链（认证注入、业务状态码检查、数据解包、Toast 提示）。它是所有 API composable（`useApiFetch`、`useLazyApiFetch` 等）的底层引擎。

## 用法

```ts
const { $api } = useNuxtApp()

// GET 请求（数据已自动解包）
const users = await $api<User[]>('/users')

// POST 请求
const user = await $api<User>('/users', {
  method: 'POST',
  body: { name: 'test', email: 'test@example.com' }
})

// PUT 请求
const updated = await $api<User>(`/users/${id}`, {
  method: 'PUT',
  body: { name: 'new-name' }
})

// DELETE 请求
await $api(`/users/${id}`, { method: 'DELETE' })
```

::note
`$api` 返回的数据已经过拦截器自动解包（提取 `dataKey` 字段），泛型 `T` 直接对应业务数据类型。
::

## 多端点切换

使用 `$api.use(endpoint)` 切换到指定端点：

```ts
const { $api } = useNuxtApp()

// 使用默认端点
const users = await $api('/users')

// 切换到 admin 端点
const adminUsers = await $api.use('admin')('/users')

// 保存端点引用，避免重复 use()
const adminApi = $api.use('admin')
const config = await adminApi('/config')
const stats = await adminApi('/stats')
```

端点实例内部有缓存机制，多次调用 `$api.use('admin')` 返回同一实例。

## 数据解包与业务校验

`$api` 默认按 `response.dataKey` 抽取业务数据并按 `successCodes` 校验业务码；`unwrap` / `businessCheck` 两个开关可在全局、端点、请求三层声明，优先级为请求显式值 > 端点 > 全局。下拉切换模式观察返回结构差异：

- `default`：按默认 `data` 字段抽取业务数据，调用方直接拿到去信封后的对象。
- `no-unwrap`：`unwrap: false` 不重写 `response._data`，保留完整 `code/message/data` 信封。
- `no-business-check`：legacy 接口未返回 `code` 字段，`businessCheck: false` 关闭校验后仍按 `dataKey` 解包出业务数据。
- `combined`：外部接口信封非标，两项同时关闭由调用方完全自处理响应。

### 端点级声明

直接返回数组或裸对象（没有 `{ code, data }` 信封）是端点的固有属性，在端点 `response` 上声明一次，该端点的所有请求（含上传、下载、流式）都按此处理：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  movk: {
    api: {
      endpoints: {
        sensor: {
          baseURL: process.env.NUXT_SENSOR_URL,
          response: { businessCheck: false, unwrap: false }
        }
      }
    }
  }
})
```

```ts
// 直接拿到数组
const points = await $api.use('sensor')<SensorPoint[]>('/point-numbers')

// 请求显式值优先：对该端点单次重新开启业务码校验
await $api.use('sensor')('/legacy', { businessCheck: true })
```

::note
开启校验时，响应体为 `null`、字符串、数组等非对象会判为业务失败（`error.data.kind` 为 `business`），不会抛 `TypeError`。
::

## Toast 提示

`$api` 内置 Toast 提示，按 `toast.successCodes` 判定成功 / 失败；支持全局默认 + 请求级覆盖两层定制。下拉切换模式、配合「注入错误」开关观察成功 / 失败两条分支：

- `default`：未传 `toast` 时继承全局配置，成功 / 错误均按默认样式弹出。
- `silent`：`toast: false` 关闭所有单次提示。
- `message`：`successMessage` / `errorMessage` 替换默认文案。
- `error-only`：`{ success: false }` 关闭成功提示但保留错误提示。
- `custom`：成功 / 错误分别覆盖 `color`、`icon` 等 ToastProps。

::note
全局或端点配置 `toast.success.methods` 可让成功提示只在 POST / PUT / PATCH / DELETE 等变更类请求上弹出；此时请求级 `{ success: { show: true } }` 或 `successMessage` 仍可为单个 GET 请求开启提示。
::

## 在事件处理器中使用

事件处理器中使用 `$api` 是最常见的场景：

```vue
<script setup lang="ts">
const { $api } = useNuxtApp()

// 表单提交
async function handleCreate(formData: CreateUserRequest) {
  try {
    const user = await $api<User>('/users', {
      method: 'POST',
      body: formData
    })
    // Toast 已自动显示，无需手动处理
    navigateTo(`/users/${user.id}`)
  }
  catch (error) {
    // 业务错误 Toast 已自动显示
    // 此处可做额外逻辑（如表单字段高亮）
  }
}

// 删除确认
async function handleDelete(id: string) {
  await $api(`/users/${id}`, { method: 'DELETE' })
  await refreshNuxtData() // 刷新页面缓存数据
}
</script>
```

## 在 useAsyncData 中使用

当需要聚合多个接口或做复杂数据处理时，在 `useAsyncData` 中使用 `$api`：

```ts
const { $api } = useNuxtApp()

// 聚合多个接口
const { data: dashboard } = await useAsyncData('dashboard', async () => {
  const [users, stats, recent] = await Promise.all([
    $api<User[]>('/users'),
    $api<Stats>('/stats'),
    $api<Activity[]>('/activity/recent')
  ])
  return { users, stats, recent }
})
```

### 封装自定义 composable

```ts [app/composables/useDashboard.ts]
export function useDashboard() {
  const { $api } = useNuxtApp()

  return useAsyncData('dashboard', async () => {
    const [users, stats] = await Promise.all([
      $api<User[]>('/users'),
      $api<Stats>('/stats')
    ])
    return { users, stats }
  })
}
```

### 业务操作 composable

对于删除、审批等写操作，将 `$api` 调用封装到独立的 composable 中，保持页面文件精简：

```ts [app/composables/useUserActions.ts]
export function useUserActions() {
  const { $api } = useNuxtApp()

  async function remove(id: string) {
    await $api(`/users/${id}`, { method: 'DELETE' })
    await refreshNuxtData()
  }

  async function create(data: CreateUserRequest) {
    return await $api<User>('/users', {
      method: 'POST',
      body: data,
    })
  }

  async function updateRole(id: string, role: UserRole) {
    return await $api<User>(`/users/${id}/role`, {
      method: 'PUT',
      body: { role },
      toast: { successMessage: '角色已更新' },
    })
  }

  return { remove, create, updateRole }
}
```

```vue [app/pages/users/index.vue]
<script setup lang="ts">
// 数据获取用 useApiFetch
const { data: users, refresh } = await useApiFetch<User[]>('/users')

// 写操作用 $api composable
const { remove, updateRole } = useUserActions()
</script>
```

## 请求级配置

请求级选项与 ofetch 选项写在同一层，`$api`、`useApiFetch`、上传下载与流式请求写法一致：

```ts
const { $api } = useNuxtApp()

// 禁用 Toast
await $api('/users', { toast: false })

// 自定义 Toast 消息
await $api('/users', {
  method: 'POST',
  body: formData,
  toast: { successMessage: '创建成功' }
})

// 全局关闭成功提示时，单次请求开启
await $api('/users', { toast: { success: { show: true } } })

// 关闭业务状态码检查（仍按 dataKey 解包）
const data = await $api('/external-api/data', { businessCheck: false })
```

用户传入的 `onRequest` / `onResponse` 等钩子与内置拦截器组合执行（内置在前），不会覆盖认证、业务校验、解包与 Toast：

```ts
await $api('/users', {
  onResponse({ response }) {
    // response._data 已按策略解包
  }
})
```

::note
这些选项经 ofetch 的 `FetchOptions` 类型扩展声明，仅 Movk Nuxt 的 `$api` 客户端识别；原生 `$fetch` 会忽略它们。
::

## 错误处理

`$api` 抛出的所有错误都是 `ApiError`（`NuxtError<ApiErrorData>`），按 `error.data.kind` 区分 `business`、`http`、`network`、`timeout`、`aborted`。错误 Toast 与 `movk:api:error` 在 ofetch 重试结束后只触发一次，主动中止不上报：

```ts
try {
  await $api('/orders', { method: 'POST', body })
}
catch (error) {
  const { kind, code } = (error as ApiError).data ?? {}
  if (kind === 'business' && code === 40001) {
    // 业务码分支
  }
}
```

## API

### ApiInstance

`$api` 的类型定义：

```ts
type ApiInstance = $Fetch & {
  use: (endpoint: string) => ApiInstance
  stream: <T>(url: string, options?: ApiStreamOptions<T>) => Promise<AsyncGenerator<T>>
}
```

::field-group
  ::field{name="$api(url, options)" type="Promise<T>"}
  发送 API 请求。支持所有 ofetch 选项，额外支持 `ApiRequestOptions` 中的字段。`$api.raw` 返回完整响应，走同一条管线。
  ::

  ::field{name="$api.use(endpoint)" type="ApiInstance"}
  切换到指定端点，返回该端点的 `$api` 实例。`endpoint` 类型为 `MovkApiEndpointName`（由模块按 `movk.api.endpoints` 声明合并出的字面量联合）。端点实例内部有缓存，多次调用返回同一实例。
  ::
::

### ApiRequestOptions

与 ofetch 选项同层传入的请求级配置：

::field-group
  ::field{name="toast" type="RequestToastOptions | false"}
  Toast 提示配置。设为 `false` 禁用所有 Toast；`{ success: { show: true } }` 可覆盖全局关闭单次开启。
  ::

  ::field{name="businessCheck" type="boolean"}
  是否按 `successCodes` 校验业务状态码。未传时继承端点 / 全局 `response.businessCheck`；设为 `false` 时不抛业务 `ApiError`，但仍按 `dataKey` 解包。
  ::

  ::field{name="unwrap" type="boolean"}
  是否按 `dataKey` 解包。未传时继承端点 / 全局 `response.unwrap`；设为 `false` 时拦截器不重写 `response._data`，调用方拿到原始响应体。与 `businessCheck` 正交。
  ::
::

### ApiError

```ts
type ApiError = NuxtError<ApiErrorData>

interface ApiErrorData {
  kind: 'business' | 'http' | 'network' | 'timeout' | 'aborted'
  endpoint: string
  code?: number | string
  response?: unknown
}
```

::field-group
  ::field{name="statusCode" type="number"}
  HTTP 失败时为状态码；业务失败时业务码落在 100–599 内取业务码，否则为 `500`。
  ::

  ::field{name="message" type="string"}
  错误文案，优先取响应体中 `messageKey` 字段。
  ::

  ::field{name="data.kind" type="ApiErrorKind"}
  错误分类：`business` 业务码校验失败、`http` HTTP 4xx/5xx、`network` 未拿到响应、`timeout` 超时、`aborted` 主动中止。
  ::

  ::field{name="data.code" type="number | string"}
  原始业务码（`business`）或 HTTP 状态码（`http`）。
  ::

  ::field{name="data.response" type="unknown"}
  原始响应体。
  ::
::
