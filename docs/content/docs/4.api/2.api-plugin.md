## 什么时候用

`$api` 是 `api.factory` 插件注入的命令式客户端，也是 `useApiFetch` 系列的底层实现。在事件处理器（提交、删除）、`useAsyncData` 聚合请求或自定义 composable 中使用；页面取数优先用 [`useApiFetch`](/docs/api/use-api-fetch)。

::note
不要直接用 `$fetch` 调业务接口，它会绕过认证、业务码校验、解包与 Toast。
::

## 用法

```ts
const { $api } = useNuxtApp()

// 返回值已按 dataKey 解包
const users = await $api<User[]>('/users')

const user = await $api<User>('/users', {
  method: 'POST',
  body: { name: 'Alice' },
  toast: { successMessage: '创建成功' }
})
```

`$api.raw()` 返回完整响应对象（`_data` 同样已解包），走同一条管线。

请求级选项 `toast`、`businessCheck`、`unwrap` 与 ofetch 选项写在同一层，`$api`、`useApiFetch`、上传下载与流式请求写法一致。用户传入的 `onRequest` / `onResponse` 在内置钩子之后执行，不会覆盖认证、校验、解包与 Toast：

```ts
await $api('/users', {
  onResponse({ response }) {
    // response._data 已按策略解包
  }
})
```

## 多端点

在 `movk.api.endpoints` 中声明端点，`$api.use(name)` 切换到对应端点的客户端。端点实例按名称缓存，多次调用返回同一实例；名称不存在时打印警告并回落到默认端点：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  movk: {
    api: {
      defaultEndpoint: 'default',
      endpoints: {
        default: { baseURL: '/api' },
        v2: { baseURL: '/api/v2' }
      }
    }
  }
})
```

```ts
const { $api } = useNuxtApp()

const profile = await $api.use('v2')<Profile>('/profile')

// useApiFetch 系列与上传下载、流式请求用 endpoint 选项
const { data } = await useApiFetch<Profile>('/profile', { endpoint: 'v2' })
```

`endpoint` 与 `$api.use()` 的参数类型是由 `movk.api.endpoints` 生成的端点名联合，拼写错误会在编辑器中报错。

### 端点配置

每个端点可独立覆盖全局的 `auth`、`toast`、`response`，与全局配置深度合并（`toast.*.methods` 整体覆盖而非拼接）。请求头分两类：

- `publicHeaders`：进入 public runtimeConfig，服务端与客户端请求都会携带，只放非机密的固定头（API 版本、租户标识）。
- `headers`：仅保存在服务端 runtimeConfig，**只有 SSR 阶段发出的请求会携带**，客户端请求不会带上。同名键优先于 `publicHeaders`。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  movk: {
    api: {
      endpoints: {
        partner: {
          baseURL: 'https://partner.example.com',
          headers: { 'X-Secret-Key': process.env.PARTNER_SECRET! },
          publicHeaders: { 'X-Api-Version': '2' },
          toast: { success: { show: false } }
        }
      }
    }
  }
})
```

## 认证

`auth.enabled` 为 `true` 时，每次请求在发送前读取 token，按 `headerName`（默认 `Authorization`）与 `tokenType`（默认 `Bearer`）注入请求头。token 来源由 `tokenSource` 决定：

- `'session'`（默认）：从 `nuxt-auth-utils` 的 `useUserSession()` 会话中按 `sessionTokenPath`（默认 `token`，支持 `user.accessToken` 这类嵌套路径）读取。模块会自动注册 `nuxt-auth-utils`，生产环境需设置至少 32 个字符的 `NUXT_SESSION_PASSWORD`。
- `'public-runtime-config'`：从 `runtimeConfig.public` 中按 `tokenPath`（默认 `apiToken`）读取。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  movk: {
    api: {
      auth: {
        enabled: true,
        sessionTokenPath: 'user.accessToken',
        unauthorized: { redirect: true, loginPath: '/login', clearSession: true }
      }
    }
  }
})
```

认证头最后写入，优先级高于请求级同名 `headers`。收到 HTTP 401 或业务码 401 时，默认按 `auth.unauthorized` 清除会话并跳转 `loginPath`；需要刷新 token 等自定义处理时使用 [`movk:api:unauthorized`](/docs/api/hooks#movkapiunauthorized)。

## 响应策略

两个开关决定 2xx 响应如何处理，二者正交：

- `businessCheck`：是否按 `successCodes` 校验 `codeKey` 字段，失败时抛出 `kind: 'business'` 的 `ApiError`。关闭后任何 2xx 都视为成功。
- `unwrap`：是否按 `dataKey` 取出业务数据。关闭后拿到原始响应体。

两者都可在全局 `response`、端点 `response`、请求级三层声明，优先级为请求显式值 > 端点 > 全局 > 默认开启。下拉切换模式观察返回结构：

::component-example
---
name: ApiUnwrapExample
options:
  - name: mode
    label: 模式
    items: ['default', 'no-unwrap', 'no-business-check', 'combined']
    default: default
---
::

- `default`：校验通过后返回 `data` 字段。
- `no-unwrap`：保留完整 `{ code, message, data }` 信封。
- `no-business-check`：接口没有 `code` 字段，关闭校验后仍按 `dataKey` 解包。
- `combined`：第三方接口没有信封，两项同时关闭由调用方自行处理。

直接返回数组或裸对象是端点的固有属性，应在端点上声明一次，该端点的所有请求（含上传、下载、流式）都按此处理：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  movk: {
    api: {
      endpoints: {
        sensor: {
          baseURL: 'https://sensor.example.com',
          response: { businessCheck: false, unwrap: false }
        }
      }
    }
  }
})
```

```ts
const points = await $api.use('sensor')<SensorPoint[]>('/points')

// 请求显式值优先：单次重新开启业务码校验
await $api.use('sensor')('/legacy', { businessCheck: true })
```

::warning
开启解包时，响应体缺少 `dataKey` 字段（或不是普通对象）会得到 `undefined`。裸数组接口只关闭 `businessCheck` 不够，必须同时关闭 `unwrap`。开启校验时，`null`、字符串、数组等非对象响应一律判为业务失败。
::

## Toast 提示

成功与失败默认各弹一次 Toast，文案优先取响应体的 `messageKey` 字段（缺省回退 `message`、`msg`），再回退到「操作成功」/ 错误分类的默认文案。请求级 `toast` 可整体关闭或局部覆盖：

```ts
await $api('/users', { toast: false }) // 全部关闭
await $api('/users', { toast: { success: false } }) // 只保留错误提示
await $api('/users', { toast: { successMessage: '已保存', errorMessage: '保存失败' } })
await $api('/users', {
  toast: {
    success: { color: 'primary', icon: 'i-lucide-sparkles' },
    error: { duration: 5000 }
  }
})
```

开关优先级：请求级 `show` 显式值 > 请求级 `successMessage` / `errorMessage` > 全局（或端点）`success.show` / `error.show` 与 `methods` 白名单 > 全局 `enabled`。因此全局关闭成功提示时，请求级 `{ success: { show: true } }` 或 `successMessage` 都会单次开启；明确静默请传 `{ success: false }`。

只为变更类请求弹成功提示时，在全局或端点配置方法白名单（大小写不敏感，请求级不接受该字段）：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  movk: {
    api: {
      toast: {
        success: { methods: ['POST', 'PUT', 'PATCH', 'DELETE'] }
      }
    }
  }
})
```

## 错误模型

所有失败统一为 `ApiError`（即 `NuxtError<ApiErrorData>`），`$api` 抛出的错误与 `useApiFetch` 的 `error.value` 是同一形态，按 `error.data.kind` 区分：

| `kind` | 触发条件 | `statusCode` | `data.code` |
| --- | --- | --- | --- |
| `business` | 2xx 但业务码不在 `successCodes` 内 | 业务码在 100–599 内时取业务码，否则 `500` | 原始业务码 |
| `http` | HTTP 4xx / 5xx | HTTP 状态码 | HTTP 状态码 |
| `network` | 未拿到响应（断网、连接被重置） | `500` | - |
| `timeout` | 超出 `timeout` 毫秒数 | `500` | - |
| `aborted` | 主动中止 | `500` | - |

`message` 优先取响应体中的 `messageKey` 字段；`data.response` 为原始响应体，`data.endpoint` 为发起请求的端点名。错误 Toast 与 `movk:api:error` 在 ofetch 重试结束后只触发一次，主动中止不上报。

```ts
import type { ApiError } from '@movk/nuxt'

try {
  await $api('/orders', { method: 'POST', body })
}
catch (error) {
  const { kind, code, response } = (error as ApiError).data ?? {}
  if (kind === 'business' && code === 40001) {
    // 业务分支
  }
  else if (kind === 'http' && code === 422) {
    // response 携带字段级校验信息
  }
}
```

## API

### ApiInstance

```ts
type ApiInstance = $Fetch & {
  use: (endpoint: MovkApiEndpointName) => ApiInstance
  stream: <T = unknown>(url: string, options?: ApiStreamOptions<T>) => Promise<AsyncGenerator<T>>
}
```

`stream()` 见 [流式请求](/docs/api/stream#apistream)。

### ApiRequestOptions

与 ofetch 选项同层传入的请求级选项：

::field-group
  ::field{name="toast" type="RequestToastOptions | false"}
  Toast 配置。`false` 关闭本次所有提示；对象形式含 `success`、`error`（`ToastProps` 加 `show`，或 `false`）与 `successMessage`、`errorMessage`。
  ::

  ::field{name="businessCheck" type="boolean"}
  是否按 `successCodes` 校验业务码。未传时继承端点 / 全局 `response.businessCheck`。
  ::

  ::field{name="unwrap" type="boolean"}
  是否按 `dataKey` 解包。未传时继承端点 / 全局 `response.unwrap`。
  ::
::

### ApiError

```ts
type ApiError = NuxtError<ApiErrorData>

interface ApiErrorData {
  kind: 'business' | 'http' | 'network' | 'timeout' | 'aborted'
  endpoint: string
  code?: number | string
  response?: unknown
}
```
