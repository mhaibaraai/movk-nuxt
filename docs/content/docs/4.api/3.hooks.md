## 什么时候用

需要对所有请求统一做某件事、又不想在每个调用处重复时使用：请求日志与埋点、全局错误上报（Sentry 等）、401 时刷新 token。单个请求的处理用请求级 `onRequest` / `onResponse` 或 `transform` 即可。

Hook 覆盖 `$api`、`useApiFetch` 系列、上传、下载与流式请求，类型已注册到 `RuntimeNuxtHooks`，`nuxtApp.hook('movk:api:...')` 有完整的类型推断。

## 用法

在 Nuxt 插件中注册全局逻辑：

```ts [app/plugins/api-hooks.ts]
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('movk:api:request', (context) => {
    console.info(`[API] ${context.options.method || 'GET'} ${context.request}`)
  })

  nuxtApp.hook('movk:api:error', (context, error) => {
    if (error.data?.kind === 'network') return
    reportError(error, { url: context.request, endpoint: error.data?.endpoint })
  })
})
```

只在某个页面生效时，在组件中注册并在卸载时注销：

```ts
const nuxtApp = useNuxtApp()
const off = nuxtApp.hook('movk:api:error', (_context, error) => {
  // 页面级错误处理
})
onUnmounted(off)
```

## 可用 Hooks

### `movk:api:request`

认证头注入与 debug 日志之后、请求发出之前触发，可修改 `context.options`（如追加请求头）。

```ts
'movk:api:request': (context: FetchContext) => void | Promise<void>
```

### `movk:api:response`

业务码校验通过并解包后触发，`context.response._data` 已是按策略处理后的业务数据。流式响应（SSE、二进制下载）跳过校验与解包，同样会触发，此时 `_data` 为原始流。

```ts
'movk:api:response': (context: FetchContext & { response: FetchResponse<any> }) => void | Promise<void>
```

### `movk:api:error`

业务码校验失败、HTTP 4xx/5xx、网络中断或超时时触发。在 ofetch 重试结束后**只触发一次**，主动中止不触发。`error` 是归一后的 [`ApiError`](/docs/api/api-plugin#错误模型)。

```ts
'movk:api:error': (context: FetchContext, error: ApiError) => void | Promise<void>
```

### `movk:api:unauthorized`

HTTP 401 或业务码（`codeKey`，兼容字符串 `'401'`）为 401 时，在 `movk:api:error` **之前**触发，上传、下载请求同样适用。

```ts
'movk:api:unauthorized': (context: FetchContext, result: { handled: boolean }) => void | Promise<void>
```

将 `result.handled` 设为 `true` 表示业务侧已接管：跳过默认的清除会话与跳转登录，也不再派发 `movk:api:error`。任一监听器设置即生效。

::note
接管后本次请求仍以 `ApiError` 失败，错误 Toast 照常弹出（请求级 `toast: false` 可关闭），原请求不会自动重试；需要重放时由调用方在刷新成功后重新发起。
::

刷新 token 的写法：

```ts [app/plugins/token-refresh.ts]
export default defineNuxtPlugin((nuxtApp) => {
  let refreshing: Promise<void> | null = null

  nuxtApp.hook('movk:api:unauthorized', async (_context, result) => {
    try {
      refreshing ??= $fetch('/api/auth/refresh', { method: 'POST' }).then(() => {})
      await refreshing
      await nuxtApp.runWithContext(() => useUserSession().fetch())
      result.handled = true
    }
    catch {
      // 刷新失败时不设置 handled，走默认的清除会话与跳转
    }
    finally {
      refreshing = null
    }
  })
})
```

## 执行顺序

```text
请求发起
  ├── 认证头注入 -> debug 日志 -> movk:api:request
  ├── 发送请求
  ├── 2xx 响应
  │   ├── 流式响应 -> movk:api:response（不校验、不解包、无成功 Toast）
  │   ├── 业务成功 -> 解包 -> movk:api:response -> 成功 Toast
  │   └── 业务失败 -> 进入出口
  ├── 4xx/5xx -> 按 retry 重试，仍失败则进入出口
  ├── 网络中断 / 超时 -> 进入出口
  └── 出口（每次请求只执行一次，主动中止跳过）
      ├── 归一为 ApiError
      ├── [401] movk:api:unauthorized -> 未接管时清除会话 + 跳转登录
      ├── movk:api:error（401 已接管时跳过）
      ├── 错误 Toast
      └── 抛出 ApiError
```
