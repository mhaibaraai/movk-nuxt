## 概述

v2 重新聚焦 Schema 驱动的中后台能力（AutoForm、SearchForm、DataTable、API），移除了与 Nuxt UI 重叠或复用价值较低的组件。下文汇总升级时需要核对的行为变化与替代方案。

## 升级步骤

1. **确认运行环境**。核对版本要求，再更新依赖和锁文件。见 [环境与 API](#环境与-api)。
2. **替换已移除的用法**。检查 [组件与类型](#移除的组件) 和 [AutoForm 控件](#移除的-autoform-控件类型)。
3. **核对行为变化**。检查 [表单、表格与语言](#表单表格与语言) 以及 [API 迁移表](/docs/api#从-v1-迁移到-v2)。
4. **验证迁移结果**。运行项目的 lint、类型检查、测试和构建，回归项目使用到的流程。

## 用 AI 迁移

在项目根目录打开 AI 编程助手，展开并复制提示词，或让助手读取 [本页的 Markdown 版本](/raw/docs/getting-started/migration.md)。提示词以 `v1.8.3` 为比较基准，也会检查项目是否需要补做更早的 v1 升级。

::collapsible{name="完整迁移提示词"}

```text
请把当前项目的 @movk/nuxt 从 v1 迁移到 v2，保留现有业务流程、数据格式和交互。

先读取项目说明、package.json、锁文件、Nuxt 或 Vite 配置、app.config、应用入口和 CI 配置。确认实际的 v1 版本、要安装的 v2 版本、包管理器，以及项目使用 Nuxt 还是 Vue + Vite。用目标版本的源码、类型声明和迁移指南核对下面的清单。若项目早于 v1.8.3，也检查实际版本到 v1.8.3 之间的差异。记录每项命中的文件和预期改动，再修改已用到的功能。

参考资料

- 文档索引 https://nuxt.mhaibaraai.cn/llms.txt

迁移清单

1. 环境与依赖
   - 将开发、CI 和部署环境的 Node.js 对齐到 ^22.22.3 || ^24.15.0 || >=26.0.0。Nuxt 模式要求 Nuxt ^4.6.4，并使用兼容的 Nuxt UI 4（至少 4.13.0）和 Zod 4（至少 4.3.6）。使用项目现有包管理器更新依赖和锁文件。
   - Vue + Vite 项目检查 @movk/nuxt/vite、virtual:movk-plugins 与 CSS 入口。API 集成、上传下载和流式请求依赖 Nuxt。保留唯一的 Tailwind CSS 入口及 @import "@movk/nuxt"。
   - 若项目单独锁定了 reka-ui，则与目标 Nuxt UI 对齐。若直接依赖 nuxt-site-config、tailwind-variants 或相关模块，检查跨主版本的配置与类型兼容。maska 和 colortranslator 已从模块移除，项目自己的调用仍需相应依赖。

2. 移除的组件、类型与主题
   - 按项目实际组件前缀搜索模板、导入、组件类型和主题配置。迁移 WithClear、WithCopy、WithPasswordToggle、WithCharacterLimit、WithFloatingLabel、AsPhoneNumberInput 为 Nuxt UI 输入组件组合。
   - PillGroup 按单选、多选、切换面板的实际用途换成 URadioGroup、UCheckboxGroup、UToggleGroup 或 UTabs。ColorChooser 可用 UColorPicker 和 UPopover 组合。Popconfirm 可用 UPopover 或 useMessageBox().confirm。SlideVerify 需要项目提供实现，保留原有验证流程。
   - 检查自定义包装组件的 v-model、事件、插槽、可访问性和主题样式。移除旧组件的类型导入和对应主题条目。

3. AutoForm 与 SearchForm
   - 检查 schema 中的 withClear、withCopy、withPasswordToggle、withCharacterLimit、withFloatingLabel、asPhoneNumberInput、colorChooser、slideVerify、pillGroup。简单场景使用现有控件和 controlProps，需要保留增强交互时通过 defineControl 注册自定义控件并传入 controls。
   - 将 AutoForm 的 :state 改为 v-model，表单绑定类型使用 z.input，并按 schema 的输出类型检查提交回调。reset() 恢复基线并补齐 schema 默认值，clear() 只保留默认值。两者原地更新状态，AutoForm 的事件带状态快照。编辑表单异步加载记录后，用 setBaseline() 设置重置目标。
   - 检查条件显示对嵌套对象、布局字段、校验和提交值的影响。meta.if 隐藏的字段不参与校验，hiddenValue 控制是否清除模型里的值，字段级策略优先。核对依赖隐藏字段的校验和提交逻辑。
   - SearchForm 的受控展开使用 v-model:expanded，初始展开可用 defaultExpanded。默认提交会修剪字符串、移除空字符串、null 和 undefined，保留 0 与 false。需要原值时用 :transform-payload="false"，或传自定义函数。检查 reset/clear 事件中完整的 schema 字段及清空后的 undefined，尤其是用对象合并更新筛选条件的代码。SearchForm 仅渲染支持的叶子字段，跳过对象、数组字段和布局容器。
   - 项目需要时再采用异步选项 asyncItems、数组项移动和复制、toggle / toggleGroup、isDirty / dirtyFields。启用 syncQuery 时，在 Nuxt 或 Vue Router 下检查首次恢复、前进与后退、query-restore 后刷新列表，以及替换或追加历史的行为。

4. DataTable 与 Tree
   - 将表格操作确认的 confirmText / cancelText / confirmButtonProps / cancelButtonProps 改为 confirmLabel / cancelLabel / confirmButton / cancelButton。把 paginationUi.text 改为完整模板，键为 empty、total、range、rangeUnknown、selected、pageSize，核对分页文档中的占位符。
   - 回归客户端与服务端分页、树形展开、选中行和无限滚动。使用 key 数组的选中、展开、列显隐状态时，检查对应 v-model 的绑定与初始值。检查空表格加载时的骨架屏，skeletonRows: 0 可使用 UTable 默认加载样式，已定义的 loading 插槽优先。
   - 按需采用 columnSettings、persistKey 和 CSV 导出。exportCsv 只处理传给表格的数据，服务端分页需要全量导出时使用 exportServerCsv 和 serverCsvExport，并传入页面的外部筛选条件。
   - Tree 回归父子级联、禁用节点、搜索前后选中与展开状态、懒加载失败重试。按需使用 leaf 策略、searchMethod / searchDebounce、reload()、getNode()、loadError 和 searchError。

5. 语言、日期与主题
   - AutoForm、SearchForm、DataTable、Tree、DatePicker 和 MessageBox 的默认文案跟随 UApp locale，缺省回退英文。要保留中文则设置 <UApp :locale="zh_cn">。自定义文案可用 extendMovkLocale，组件已有的文案 props 也可继续使用。
   - movk.zod 的校验文案本地化按需开启。locale: 'auto' 在客户端跟随 UApp，服务端用 fallback。movk:zod:config 的 customError 仅作用于当前应用的 AutoForm 和 SearchForm。Vue + Vite 通过插件选项 zod.customError 配置。检查直接调用 Zod 的校验以及自定义错误映射。
   - useDateFormatter 未传 locale 时跟随 UApp，组件外回退 en。确认 toDate 对带时间值保留时分秒，convertData 保留原生 Date 和类实例。DatePicker 使用 v-model:open 控制弹层，popoverProps.defaultOpen 仅用于初始化非受控状态。检查 open() / close()、负时区、月和年模式的显示，以及表单字段尺寸和禁用态。
   - 检查自定义主题前缀、中性色板及 SSR 首屏颜色。自定义组件前缀的项目同时验证 useMessageBox 的命令式调用。

6. API、认证与文件传输（Nuxt）
   - 搜索 $api（含 .use、.raw 和 .stream）、useApiFetch 及其变体、上传下载、chat transport 和 movk:api:* 钩子。将 skipBusinessCheck / skipUnwrap 改为语义取反的 businessCheck / unwrap，未设置的选项继续继承端点和全局配置。把 $api 的这些选项和 toast 从 context 移到请求选项顶层。
   - 业务码检查与 dataKey 解包独立。直接返回裸数组或裸对象的端点，在 endpoints.<name>.response 中同时设置 businessCheck: false 和 unwrap: false。按请求覆盖端点默认值。自定义 onRequest / onResponse 会在内置钩子之后执行，依赖原始响应的调用应显式设置 unwrap: false。
   - 用 ApiError.data?.kind 判断 business、http、network、timeout、aborted，按需读取 data.code 和 data.response。更新原先使用 FetchError、isBusinessError、error.response 或把 error.data 当成响应体的代码。movk:api:error 改为 (context, error)，在重试结束后最多上报一次，主动中止不触发错误上报。检查 401、Toast、重试和 SSR 认证。
   - 上传 timeoutMs 改为 timeout。上传下载继承端点的 publicHeaders 和请求钩子，注入的认证头优先于普通 headers。仅关闭业务校验时仍会解包。检查下载缺少 Content-Length 时的进度、JSON 错误响应及中止行为。SSE 和 chat transport 按流读取，JSON 错误仍按端点策略处理。
   - 若使用 nuxt-auth-utils 会话，从 v0.5 升到 v0.6 时，按上游指南迁移会话配置、服务端 helpers 和部署环境。生产环境需设置 NUXT_APP_SECRET，移除旧的 NUXT_SESSION_PASSWORD 和 runtimeConfig.session.password，并安排用户重新登录。报告部署所需的变量名，保留密钥值在部署环境中。

7. 文档和 AI 集成
   - 更新项目引用的 Movk Nuxt 文档链接。旧 composables 页按能力合并，SearchForm 归入 AutoForm，上传下载和流式请求归入 API，MCP、llms.txt 和 Skills 归入 AI 集成页。

改完后运行项目已有的 lint、类型检查、测试和构建，回归本次命中的表单提交、分页、认证或文件传输等流程。汇报修改的文件、核对结果、还需人工处理的部署项，以及无法验证的项目。
```

## 移除的组件

| 组件 | 替代方案 |
| --- | --- |
| `MWithClear` | `UInput` 组合写法，见 [Nuxt UI Input 示例](https://ui.nuxt.com/docs/components/input#with-clear-button) |
| `MWithCopy` | `UInput` 组合写法，见 [Nuxt UI Input 示例](https://ui.nuxt.com/docs/components/input#with-copy-button) |
| `MWithPasswordToggle` | `UInput` 组合写法，见 [Nuxt UI Input 示例](https://ui.nuxt.com/docs/components/input#with-password-toggle) |
| `MWithCharacterLimit` | `UInput` 组合写法，见 [Nuxt UI Input 示例](https://ui.nuxt.com/docs/components/input#with-character-limit) |
| `MWithFloatingLabel` | `UInput` 组合写法，见 [Nuxt UI Input 示例](https://ui.nuxt.com/docs/components/input#with-floating-label) |
| `MAsPhoneNumberInput` | `UInput` 组合写法，见 [Nuxt UI Input 示例](https://ui.nuxt.com/docs/components/input#as-a-phone-number-input) |
| `MPillGroup` | 按用途选择 `URadioGroup` / `UCheckboxGroup` 的 `variant="card"`、`UToggleGroup` 或 `UTabs` |
| `MColorChooser` | `UColorPicker` 放入 `UPopover` |
| `MSlideVerify` | 无内置替代，可自行实现或接入第三方人机验证服务 |
| `MPopconfirm` | `UPopover` 内放置确认按钮，或使用命令式的 [`useMessageBox`](/docs/components/message-box#usemessagebox) |

同时移除了 `maska` 与 `colortranslator` 依赖，以及上述组件对应的 Props / Emits / Slots 类型导出（如 `WithClearProps`、`PillGroupProps`、`ColorChooserProps`）。

## 移除的 AutoForm 控件类型

以下 `type` 值不再内置，继续使用会渲染 `[AutoForm] No control mapped` 提示：

- `withClear`、`withPasswordToggle`、`withCopy`、`withCharacterLimit`、`withFloatingLabel`、`asPhoneNumberInput`
- `colorChooser`、`slideVerify`、`pillGroup`

简单场景可通过 `controlProps` 配置现有控件。需要保留增强输入框时，在项目内封装组件，通过 `defineControl` 注册并把 `controls` 传给表单。自定义控件可以沿用原来的 `type` 名称。

::code-group

```ts [使用内置控件]
const schema = afz.object({
  // 之前：afz.string({ type: 'withPasswordToggle' })
  password: afz.string({ controlProps: { type: 'password' } }),
  // 之前：afz.enum([...], { type: 'pillGroup' })
  category: afz.enum(['全部', '前端', '后端'], {
    type: 'radioGroup',
    controlProps: { orientation: 'horizontal' }
  })
})
```

```ts [注册自定义控件]
import PasswordInput from '~/components/PasswordInput.vue'

const { afz, controls } = useAutoForm({
  withPasswordToggle: defineControl({
    component: PasswordInput,
    controlProps: { class: 'w-full' }
  })
})
```

::

详见 [控件与自定义控件](/docs/auto-form/controls#自定义控件)。

## 表单、表格与语言

- **AutoForm 绑定**。使用 `v-model` 绑定输入状态，类型用 `z.input`。旧的 `:state` 仍可用，开发时会提示弃用。
- **表单重置与清空**。`reset()` 恢复基线并应用 schema 默认值，`clear()` 仅保留 schema 默认值。两者原地更新绑定对象并发出状态快照。编辑已有记录时，在加载后用 `setBaseline()` 设置重置目标。
- **SearchForm**。使用 `v-model:expanded` 控制展开。提交默认去除字符串首尾空白和空值，可设 `:transform-payload="false"` 保留原始数据。
- **DataTable**。操作确认改用 `confirmLabel`、`cancelLabel`、`confirmButton`、`cancelButton`。分页文案改用完整句子模板，键为 `empty`、`total`、`range`、`rangeUnknown`、`selected`、`pageSize`。
- **语言**。组件文案与 `useDateFormatter` 跟随 UApp 语言，缺省回退英文。需要中文时设定 UApp 语言，或对格式化函数传入 locale。
- **DatePicker**。`v-model:open` 优先于旧的 `popoverProps.open`，`popoverProps.defaultOpen` 仅初始化非受控状态。调用 `open()` / `close()` 前，把已有受控开关迁移到 `v-model:open`。

## 文档路径调整

文档按能力域重新组织，旧链接会自动重定向：

- `/docs/composables/*` 拆入对应能力域：`useAutoForm` → 表单、`useTheme` → 主题、`useMessageBox` / `useDateFormatter` → 对应组件页、上传下载与流式请求 → API
- AutoForm 的字段类型页合并为 [字段类型](/docs/auto-form/field-types)，`SearchForm` 移入表单章节
- AI 集成三页合并为 [AI 集成](/docs/getting-started/ai)
