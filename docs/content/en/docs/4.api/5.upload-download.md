## useUploadWithProgress

### Usage

`useUploadWithProgress` plugs an XHR adapter in as the underlying fetch of the same `$api` pipeline (the fetch spec still cannot report upload progress in mainstream browsers), so endpoint headers, auth, business validation, Toast, error normalization and `movk:api:*` hooks match `useApiFetch` exactly. The returned `data` is unwrapped per the endpoint policy and every failure is an `ApiError`.

```vue
<script setup lang="ts">
const selected = ref<File[] | null>(null)
const { progress, status, data, error, upload, abort } = useUploadWithProgress<{
  files: Array<{ name: string, size: number }>
}>()

async function handleUpload() {
  const { data, error: err, aborted } = await upload('/api/upload', selected.value!, {
    fieldName: 'files',
    onSuccess: d => console.log('Upload succeeded:', d.files)
  })

  if (aborted) return
  if (err) console.error(err)
  else console.log(data?.files)
}
</script>

<template>
  <UFileUpload v-model="selected" multiple />
  <UButton :disabled="!selected?.length" @click="handleUpload">Upload</UButton>
  <UProgress v-if="status === 'pending'" :model-value="progress ?? undefined" :max="100" />
  <UButton v-if="status === 'pending'" @click="abort">Cancel</UButton>
</template>
```

::note
Use this for scenarios that require displaying upload progress. For small files where progress is not needed, you can use [`$api`](/docs/api/api-plugin) directly.
::

### Single File, Multiple Files and Extra Fields

Pass a `File` for single-file upload or a `File[]` for multiple files (appended under the same `fieldName`); `fields` injects extra form fields submitted alongside the file:

await upload('/api/upload', [f1, f2, f3], { fieldName: 'files' })

await upload('/api/upload', file, {

### Abort Upload

```ts
const { status, upload, abort } = useUploadWithProgress()

upload('/api/upload', largeFile)

function handleCancel() {
  if (status.value === 'pending') abort()
}
```

After aborting:

- `status` changes to `'aborted'`; `progress` resets to `0`
- `error` remains `null` (not treated as failure)
- `onSuccess` / `onError` are not called; no Toast is shown
- `upload()` returns `{ data: null, error: null, aborted: true }`

### Authentication

The token is automatically read from the session and injected into the `Authorization` header. You can override it with the same header name in `headers` (user value takes priority).

```ts
await upload('/api/upload', file, {
  headers: { Authorization: 'Bearer override' }
})
```

### API

#### useUploadWithProgress&lt;T&gt;()

`useUploadWithProgress<T>(): { progress, status, data, error, upload, abort }`{lang="ts-type"}

##### Returns

::field-group
  ::field{name="progress" type="Ref<number | null>"}
  Upload progress, 0–100. Aligned with the download-side type, `null` is retained as a possible value but does not occur in practice for uploads.
  ::

  ::field{name="status" type="Ref<TransferStatus>"}
  Transfer status: `'idle' | 'pending' | 'success' | 'error' | 'aborted'`.
  ::

  ::field{name="data" type="Ref<T | null>"}
  Business data unwrapped by `dataKey`.
  ::

  ::field{name="error" type="Ref<ApiError | null>"}
  Error object. Business errors are `ApiError`; HTTP/network errors are `Error`. `null` on abort.
  ::

  ::field{name="upload()" type="(url: string, files: File | File[], options?: UploadWithProgressOptions<T>) => Promise<TransferResult<T>>"}
  Execute the upload.

    ::collapsible
      **Parameters**

      ::field-group

        ::field{name="url" type="string" required}
        ::

        ::field{name="files" type="File | File[]" required}
        ::

        ::field{name="options" type="UploadWithProgressOptions<T>"}

          ::collapsible

            ::field-group

              ::field{name="fieldName" type="string"}
              Defaults to `'file'`.
              ::

              ::field{name="fields" type="Record<string, string | Blob>"}
              ::

              ::field{name="headers" type="Record<string, string>"}
              Merged with the endpoint headers; when auth is enabled the auth header is injected last and takes the highest priority, same as `$api`.
              ::

              ::field{name="toast" type="RequestToastOptions | false"}
              ::

              ::field{name="endpoint" type="string"}
              ::

              ::field{name="businessCheck" type="boolean"}
              Whether to validate the business status code; inherits the endpoint config when omitted. When `false`, still unwraps by `dataKey`.
              ::

              ::field{name="unwrap" type="boolean"}
              Whether to unwrap by `dataKey`; inherits the endpoint config when omitted.
              ::

              ::field{name="timeout" type="number"}
              Timeout in milliseconds. 0 or omitted means no timeout.
              ::

              ::field{name="withCredentials" type="boolean"}
              ::

              ::field{name="onSuccess" type="(data: T) => void"}
              Receives the unwrapped business data.
              ::

              ::field{name="onError" type="(error: ApiError) => void"}
              ::
            ::
          ::
        ::
      ::

      **Returns**

      `Promise<TransferResult<T>>`: `{ data: T | null, error: ApiError | null, aborted: boolean }`.
    ::
  ::

  ::field{name="abort()" type="() => void"}
  Abort the current upload; `status` switches to `'aborted'`.
  ::

## useDownloadWithProgress

### Usage

`useDownloadWithProgress` reads a streamed response through `$api.raw` and reports progress, so endpoint headers, auth, business validation, Toast, error normalization and `movk:api:*` hooks match `useApiFetch` exactly; the request body is serialized by ofetch and every failure is an `ApiError`.

When the backend returns `application/json`, business validation is applied and error responses are **not** written to a file as binary. When binary data is returned, progress is calculated from `content-length`; when `content-length` is missing, `progress` is `null` and the UI can switch to indeterminate accordingly.

```vue
<script setup lang="ts">
const { progress, status, error, download, abort } = useDownloadWithProgress()

async function handleDownload() {
  const { aborted, error: err } = await download('/api/export/report', {
    filename: 'monthly-report.pdf',
    onSuccess: name => console.log('Done', name)
  })
  if (aborted) return
  if (err) console.error(err)
}
</script>

<template>
  <UButton :loading="status === 'pending'" @click="handleDownload">Download</UButton>
  <UProgress
    v-if="status === 'pending'"
    :model-value="progress ?? undefined"
    :max="100"
  />
  <UButton v-if="status === 'pending'" @click="abort">Cancel</UButton>
</template>
```

::note
Use this for large file exports, bulk downloads and similar scenarios. For small files where progress is not needed, use [`$api`](/docs/api/api-plugin) directly.
::

### Filename Resolution

Priority order:

1. `options.filename`
2. Response header `Content-Disposition` (supports RFC 5987 encoding)
3. Last segment of the URL pathname (query string is automatically stripped)
4. `'download'`

```ts
await download('/api/export?token=abc')
// Automatically uses "export" as the fallback filename; query string does not pollute the name
```
