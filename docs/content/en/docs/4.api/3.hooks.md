## When to Use It

Use hooks for logic shared by all requests, such as request logging, analytics, global error reporting through Sentry, or token refresh on 401. For a single request, use its `onRequest` / `onResponse` handler or `transform` instead.

Hooks cover `$api`, the `useApiFetch` family, uploads, downloads and streaming requests. Their types are registered in `RuntimeNuxtHooks`, giving `nuxtApp.hook('movk:api:...')` full type inference.

## Usage

Register shared logic in a Nuxt plugin:

```ts [app/plugins/api-hooks.ts]
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('movk:api:request', (context) => {
    console.info(`[API] ${context.options.method || 'GET'} ${context.request}`)
  })

  nuxtApp.hook('movk:api:error', (context, error) => {
    if (error.data?.kind === 'network') return
    reportError(error, { url: context.request, endpoint: error.data?.endpoint })
  })
})
```

For page-specific handling, register in the component and unregister on unmount:

```ts
const nuxtApp = useNuxtApp()
const off = nuxtApp.hook('movk:api:error', (_context, error) => {
  // Handle a page-specific error
})
onUnmounted(off)
```

## Available Hooks

### `movk:api:request`

Runs after auth-header injection and debug logging, before the request is sent. You can modify `context.options`, for example to add headers.

```ts
'movk:api:request': (context: FetchContext) => void | Promise<void>
```

### `movk:api:response`

Runs after successful business-code validation and unwrapping. `context.response._data` contains the data processed by the response policy. Streaming responses, such as SSE and binary downloads, skip validation and unwrapping but still trigger this hook, with the original stream in `_data`.

```ts
'movk:api:response': (context: FetchContext & { response: FetchResponse<any> }) => void | Promise<void>
```

### `movk:api:error`

Runs for failed business-code checks, HTTP 4xx/5xx responses, network failures and timeouts. It fires **only once after ofetch finishes retrying** and does not fire for explicit cancellation. `error` is the normalized [`ApiError`](/en/docs/api/api-plugin#error-model).

```ts
'movk:api:error': (context: FetchContext, error: ApiError) => void | Promise<void>
```

### `movk:api:unauthorized`

Runs **before** `movk:api:error` for HTTP 401 or business code 401 (`codeKey`, including the string `'401'`). Uploads and downloads follow the same behavior.

```ts
'movk:api:unauthorized': (context: FetchContext, result: { handled: boolean }) => void | Promise<void>
```

Set `result.handled` to `true` to take over handling: this skips default session clearing and login redirection, and prevents `movk:api:error` from firing. Setting it in any listener is sufficient.

::note
The request still fails with `ApiError` after being handled. The error Toast still appears unless disabled with request-level `toast: false`. The original request is not retried automatically; the caller must replay it after a successful refresh if needed.
::

Token refresh example:

```ts [app/plugins/token-refresh.ts]
export default defineNuxtPlugin((nuxtApp) => {
  let refreshing: Promise<void> | null = null

  nuxtApp.hook('movk:api:unauthorized', async (_context, result) => {
    try {
      refreshing ??= $fetch('/api/auth/refresh', { method: 'POST' }).then(() => {})
      await refreshing
      await nuxtApp.runWithContext(() => useUserSession().fetch())
      result.handled = true
    }
    catch {
      // Leave handled unset after refresh failure to use default session clearing and redirection
    }
    finally {
      refreshing = null
    }
  })
})
```

## Execution Order

```text
Start request
  ├── Inject auth header -> debug log -> movk:api:request
  ├── Send request
  ├── 2xx response
  │   ├── Streaming response -> movk:api:response (no validation, unwrapping or success Toast)
  │   ├── Business success -> unwrap -> movk:api:response -> success Toast
  │   └── Business failure -> enter exit pipeline
  ├── 4xx/5xx -> retry according to retry settings; enter exit pipeline if still failing
  ├── Network failure / timeout -> enter exit pipeline
  └── Exit pipeline (once per request; skipped for explicit cancellation)
      ├── Normalize to ApiError
      ├── [401] movk:api:unauthorized -> clear session + redirect unless handled
      ├── movk:api:error (skipped for handled 401)
      ├── Error Toast
      └── Throw ApiError
```
