## When to Use It

`$api` is the imperative client injected by the `api.factory` plugin and used internally by the `useApiFetch` family. Use it in submit or delete handlers, aggregated `useAsyncData` requests and custom composables. For page data, prefer [`useApiFetch`](/en/docs/api/use-api-fetch).

::note
Calling business APIs directly with `$fetch` bypasses authentication, business-code checks, unwrapping and Toast.
::

## Usage

```ts
const { $api } = useNuxtApp()

// The result is already unwrapped using dataKey
const users = await $api<User[]>('/users')

const user = await $api<User>('/users', {
  method: 'POST',
  body: { name: 'Alice' },
  toast: { successMessage: 'Created successfully' }
})
```

`$api.raw()` returns the full response object, with `_data` also unwrapped, through the same pipeline.

Pass request options `toast`, `businessCheck` and `unwrap` alongside ofetch options. The same syntax applies to `$api`, `useApiFetch`, uploads, downloads and streaming requests. User `onRequest` / `onResponse` handlers run after built-in hooks and do not replace authentication, validation, unwrapping or Toast:

```ts
await $api('/users', {
  onResponse({ response }) {
    // response._data has already been processed by the response policy
  }
})
```

## Multiple Endpoints

Declare endpoints in `movk.api.endpoints`, then switch clients with `$api.use(name)`. Clients are cached by endpoint name, so repeated calls return the same instance. An unknown name emits a warning and falls back to the default endpoint:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  movk: {
    api: {
      defaultEndpoint: 'default',
      endpoints: {
        default: { baseURL: '/api' },
        v2: { baseURL: '/api/v2' }
      }
    }
  }
})
```

```ts
const { $api } = useNuxtApp()

const profile = await $api.use('v2')<Profile>('/profile')

// useApiFetch, uploads, downloads and streaming requests use the endpoint option
const { data } = await useApiFetch<Profile>('/profile', { endpoint: 'v2' })
```

The `endpoint` option and `$api.use()` argument use a union of endpoint names generated from `movk.api.endpoints`, so misspellings produce editor errors.

### Endpoint Configuration

Each endpoint can override global `auth`, `toast` and `response` settings. Settings merge deeply, except `toast.*.methods`, which replaces the array instead of concatenating it. Headers have two categories:

- `publicHeaders`: included in public runtimeConfig and sent by both server and client requests. Use only non-secret values, such as API versions or tenant identifiers.
- `headers`: stored only in server runtimeConfig and **sent only by requests made during SSR**. Client requests do not include them. They override matching `publicHeaders` keys.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  movk: {
    api: {
      endpoints: {
        partner: {
          baseURL: 'https://partner.example.com',
          headers: { 'X-Secret-Key': process.env.PARTNER_SECRET! },
          publicHeaders: { 'X-Api-Version': '2' },
          toast: { success: { show: false } }
        }
      }
    }
  }
})
```

## Authentication

When `auth.enabled` is `true`, the client reads a token before each request and injects it using `headerName` (default `Authorization`) and `tokenType` (default `Bearer`). `tokenSource` selects the source:

- `'session'` (default): reads the `nuxt-auth-utils` `useUserSession()` session using `sessionTokenPath` (default `token`), including nested paths such as `user.accessToken`. The module automatically registers `nuxt-auth-utils`; production requires a `NUXT_SESSION_PASSWORD` of at least 32 characters.
- `'public-runtime-config'`: reads `runtimeConfig.public` using `tokenPath` (default `apiToken`).

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  movk: {
    api: {
      auth: {
        enabled: true,
        sessionTokenPath: 'user.accessToken',
        unauthorized: { redirect: true, loginPath: '/login', clearSession: true }
      }
    }
  }
})
```

The auth header is written last and takes precedence over the same request-level `headers` key. HTTP 401 and business code 401 clear the session and redirect to `loginPath` according to `auth.unauthorized` by default. Use [`movk:api:unauthorized`](/en/docs/api/hooks#movkapiunauthorized) for token refresh or other custom handling.

## Response Policies

Two independent switches control how 2xx responses are processed:

- `businessCheck`: validates `codeKey` against `successCodes` and throws an `ApiError` with `kind: 'business'` on failure. When disabled, any 2xx response is treated as successful.
- `unwrap`: extracts business data using `dataKey`. When disabled, the original response body is returned.

Both switches can be set on global `response`, endpoint `response` and individual requests. Precedence is explicit request value > endpoint > global > enabled by default. Switch modes below to inspect the result:

::component-example
---
name: ApiUnwrapExample
options:
  - name: mode
    label: 模式
    items: ['default', 'no-unwrap', 'no-business-check', 'combined']
    default: default
---
::

- `default`: returns the `data` field after validation.
- `no-unwrap`: preserves the full `{ code, message, data }` envelope.
- `no-business-check`: skips validation for a response without `code` but still unwraps with `dataKey`.
- `combined`: disables both switches for a third-party API without an envelope, leaving handling to the caller.

Returning bare arrays or objects is an endpoint property. Declare it once on the endpoint so all its requests, including uploads, downloads and streams, use the same policy:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  movk: {
    api: {
      endpoints: {
        sensor: {
          baseURL: 'https://sensor.example.com',
          response: { businessCheck: false, unwrap: false }
        }
      }
    }
  }
})
```

```ts
const points = await $api.use('sensor')<SensorPoint[]>('/points')

// An explicit request value wins: re-enable business-code checks for one request
await $api.use('sensor')('/legacy', { businessCheck: true })
```

::warning
When unwrapping is enabled, a response without `dataKey`, or a response that is not a plain object, produces `undefined`. Disabling only `businessCheck` is insufficient for bare-array APIs: disable `unwrap` as well. When checks are enabled, non-object responses such as `null`, strings and arrays are business failures.
::

## Toast Notifications

Successful and failed requests each show one Toast by default. Messages first use the response's `messageKey` field (falling back to `message` and `msg`), then the default success message or error-kind message. Request-level `toast` can disable notifications or override individual settings:

```ts
await $api('/users', { toast: false }) // Disable all notifications
await $api('/users', { toast: { success: false } }) // Keep only error notifications
await $api('/users', { toast: { successMessage: 'Saved', errorMessage: 'Save failed' } })
await $api('/users', {
  toast: {
    success: { color: 'primary', icon: 'i-lucide-sparkles' },
    error: { duration: 5000 }
  }
})
```

Visibility precedence is explicit request-level `show` > request-level `successMessage` / `errorMessage` > global (or endpoint) `success.show` / `error.show` and the `methods` allowlist > global `enabled`. Thus, `{ success: { show: true } }` or `successMessage` enables a success notification for one request even when success notifications are globally disabled. Use `{ success: false }` to explicitly silence it.

To show success notifications only for write operations, configure a method allowlist globally or on the endpoint. Matching is case-insensitive; the field is not supported at request level:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  movk: {
    api: {
      toast: {
        success: { methods: ['POST', 'PUT', 'PATCH', 'DELETE'] }
      }
    }
  }
})
```

## Error Model

All failures use `ApiError`, an alias for `NuxtError<ApiErrorData>`. Errors thrown by `$api` have the same shape as `useApiFetch`'s `error.value`. Distinguish them using `error.data.kind`:

| `kind` | Trigger | `statusCode` | `data.code` |
| --- | --- | --- | --- |
| `business` | 2xx response whose business code is not in `successCodes` | Business code if within 100–599, otherwise `500` | Original business code |
| `http` | HTTP 4xx / 5xx | HTTP status code | HTTP status code |
| `network` | No response, such as a disconnected network or reset connection | `500` | - |
| `timeout` | Exceeds `timeout` milliseconds | `500` | - |
| `aborted` | Explicit cancellation | `500` | - |

`message` prefers the response's `messageKey` field. `data.response` contains the original response body, and `data.endpoint` identifies the endpoint. The error Toast and `movk:api:error` fire only once after ofetch finishes retrying. Explicit cancellation is not reported.

```ts
import type { ApiError } from '@movk/nuxt'

try {
  await $api('/orders', { method: 'POST', body })
}
catch (error) {
  const { kind, code, response } = (error as ApiError).data ?? {}
  if (kind === 'business' && code === 40001) {
    // Handle a business-specific failure
  }
  else if (kind === 'http' && code === 422) {
    // response contains field-level validation details
  }
}
```

## API

### ApiInstance

```ts
type ApiInstance = $Fetch & {
  use: (endpoint: MovkApiEndpointName) => ApiInstance
  stream: <T = unknown>(url: string, options?: ApiStreamOptions<T>) => Promise<AsyncGenerator<T>>
}
```

See [Streaming Requests](/en/docs/api/stream#apistream) for `stream()`.

### ApiRequestOptions

Request-specific options passed alongside ofetch options:

::field-group
  ::field{name="toast" type="RequestToastOptions | false"}
  Toast settings. `false` disables all notifications for the request. The object form supports `success`, `error` (`ToastProps` plus `show`, or `false`), `successMessage` and `errorMessage`.
  ::

  ::field{name="businessCheck" type="boolean"}
  Whether to validate business codes against `successCodes`. Inherits endpoint / global `response.businessCheck` when omitted.
  ::

  ::field{name="unwrap" type="boolean"}
  Whether to unwrap using `dataKey`. Inherits endpoint / global `response.unwrap` when omitted.
  ::
::

### ApiError

```ts
type ApiError = NuxtError<ApiErrorData>

interface ApiErrorData {
  kind: 'business' | 'http' | 'network' | 'timeout' | 'aborted'
  endpoint: string
  code?: number | string
  response?: unknown
}
```
