## Overview

Module-level options belong under `movk` in `nuxt.config.ts` and take effect at build time. Every option has a default:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@movk/nuxt'],
  movk: {
    prefix: 'M',
    theme: { enabled: true },
    icon: { clientBundle: true },
    api: { enabled: true },
    zod: false
  }
})
```

Theme values that can change at runtime belong in `app.config.ts`; see [Runtime configuration](#runtime-configuration).

## `prefix`

- **Type**: `string`
- **Default**: `'M'`

The component name prefix. For example, `prefix: 'My'` registers `MyAutoForm` and `MyDataTable`. Composable names stay the same.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  movk: {
    prefix: 'My'
  }
})
```

## `theme`

Build-time theme options. See [Themes](/en/docs/getting-started/theme) for their effects.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  movk: {
    theme: {
      font: 'Alibaba PuHuiTi',
      radius: 0.375
    }
  }
})
```

::field-group
  ::field{name="enabled" type="boolean"}
  Enable the theme module. Defaults to `true`. Disabling it omits the `app.config.movk` defaults, theme plugins and `MThemePicker` components.
  ::

  ::field{name="prefix" type="string"}
  Tailwind CSS utility prefix used to generate module component theme classes. Defaults to Nuxt UI's `ui.tailwindPrefix`.
  ::

  ::field{name="font" type="string | { name: string, href?: string }"}
  Global font. Built-in fonts (`'Alibaba PuHuiTi'` and `'OPPO Sans'`) need only a name; provide a stylesheet URL for a self-hosted font. When omitted, no `--font-sans` value is injected.
  ::

  ::field{name="radius" type="number"}
  Default radius in rem. When omitted, no `--ui-radius` value is injected, so Nuxt UI's default or the project's CSS applies.
  ::

  ::field{name="radiuses" type="number[]"}
  Radius choices for `MThemePicker`, in rem. Defaults to `[0, 0.125, 0.25, 0.375, 0.5]`.
  ::

  ::field{name="neutralColors" type="string[]"}
  Neutral palette choices for `MThemePicker`. Defaults to `['slate', 'gray', 'zinc', 'neutral', 'stone', 'taupe', 'mauve', 'mist', 'olive']`.
  ::
::

::note
Configure colors with `@plugin "@nuxt/ui/colors"` in project CSS. Configure component default variants with `ui.<component>.defaultVariants` in `app.config.ts`. See [Themes · Colors](/en/docs/getting-started/theme#colors).
::

## `icon`

::field-group
  ::field{name="clientBundle" type="boolean"}
  Add icons used by module components and its built-in icon sets (Lucide, Phosphor and Tabler) to the build-time `@nuxt/icon` bundle. Defaults to `true`. When disabled, icons are requested on demand at runtime.
  ::
::

Icon data comes from installed `@iconify-json/*` packages. Collections that are not installed are skipped without failing the build. See [Themes · Icon sets](/en/docs/getting-started/theme#icon-sets).

## `api`

Configure endpoints, authentication, response parsing and Toast notifications. Available only in Nuxt mode.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  movk: {
    api: {
      endpoints: {
        default: { baseURL: '/api' },
        admin: { baseURL: '/admin-api' }
      },
      auth: { enabled: true }
    }
  }
})
```

::field-group
  ::field{name="enabled" type="boolean"}
  Enable the API domain (`$api` and the `useApiFetch` family). Defaults to `true`.
  ::

  ::field{name="defaultEndpoint" type="string"}
  Default endpoint name. Defaults to `'default'`.
  ::

  ::field{name="debug" type="boolean"}
  Log request details to the console. Defaults to `false`.
  ::

  ::field{name="endpoints" type="Record<string, ApiEndpointConfig>"}
  Endpoint registry. When omitted, includes `default: { baseURL: '/api' }`.
  ::

  ::field{name="auth" type="ApiAuthConfig"}
  Authentication injection and 401 handling.
  ::

  ::field{name="response" type="ApiResponseConfig"}
  Business status codes, response unwrapping and message fields.
  ::

  ::field{name="toast" type="ApiToastConfig"}
  Success and failure notifications.
  ::
::

::note{to="/en/docs/api/api-plugin"}
See API · Plugin and endpoints for complete field descriptions, merge precedence and security guidance.
::

::warning
The module registers `nuxt-auth-utils` only when `api.auth.enabled` is `true` and `tokenSource` is `'session'` (the default). In that case, production requires a `NUXT_SESSION_PASSWORD` of at least 32 characters.
::

## `zod`

- **Type**: `MovkZodOptions | false`
- **Default**: `false`

Localize Zod validation messages and generate required-field messages with field labels. `z.config` is a global singleton: enabling this option affects all Zod validation in the application, including the server.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  movk: {
    zod: {
      locale: 'auto',
      locales: ['zh-CN']
    }
  }
})
```

::field-group
  ::field{name="locale" type="'auto' | string" required}
  Validation language. Use a fixed locale code such as `'zh-CN'`, or `'auto'` to follow `<UApp :locale>`. Automatic selection works only on the client; the server uses `fallback`.
  ::

  ::field{name="fallback" type="string"}
  Language used when a locale cannot be mapped to Zod. Defaults to `'en'`.
  ::

  ::field{name="locales" type="string[]"}
  Languages to bundle in `'auto'` mode. When omitted, only `fallback` is bundled. Unnecessary for a fixed `locale`.
  ::

  ::field{name="localeMap" type="Record<string, string>"}
  Override mappings from locale codes to `zod/locales` export names, for example `{ 'zh-Hans': 'zhCN' }`.
  ::

  ::field{name="required" type="boolean | { inputs?: (undefined | null | '')[] }"}
  Required-field messages. `true` treats `undefined` as missing; an object customizes which values count as missing; `false` disables these messages. Defaults to `true`.
  ::

  ::field{name="label" type="boolean"}
  Include the schema metadata's `label` / `title` in required-field messages. Defaults to `true`.
  ::

  ::field{name="jitless" type="boolean"}
  Disable Zod JIT compilation for strict CSP environments that prohibit `new Function`. Defaults to `false`.
  ::
::

After enabling `zod`, use the `movk:zod:config` hook in a plugin to provide a `customError` with the highest priority:

```ts [app/plugins/zod.ts]
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('movk:zod:config', (config) => {
    config.customError = (issue) => {
      if (issue.code === 'too_small' && issue.origin === 'string') {
        return `Enter at least ${issue.minimum} characters`
      }
    }
  })
})
```

Return an empty value to continue with the required-field rules and locale messages.

## Runtime configuration

Two keys in `app.config.ts` relate to the module:

- `ui.movk<component>`: component theme overrides such as `ui.movkDataTable` and `ui.movkTree`, using the same format as Nuxt UI component themes. See [Themes · Component style overrides](/en/docs/getting-started/theme#component-style-overrides).
- `movk`: runtime theme defaults generated from the `theme` options, which can be overridden here.

```ts [app.config.ts]
export default defineAppConfig({
  movk: {
    radius: 0.5,
    icons: 'lucide',
    blackAsPrimary: false,
    picker: {
      radiuses: [0, 0.25, 0.5],
      neutralColors: ['slate', 'zinc']
    }
  }
})
```

::field-group
  ::field{name="radius" type="number"}
  Default radius in rem. Defaults to `theme.radius`.
  ::

  ::field{name="icons" type="'lucide' | 'phosphor' | 'tabler'"}
  Default icon set. Defaults to `'lucide'`.
  ::

  ::field{name="blackAsPrimary" type="boolean"}
  Use black as the default primary color (white in dark mode). Defaults to `false`.
  ::

  ::field{name="picker" type="{ radiuses?: number[], neutralColors?: string[] }"}
  Choices shown in `MThemePicker`. Defaults to `theme.radiuses` and `theme.neutralColors`.
  ::

  ::field{name="dir" type="'ltr' | 'rtl'"}
  Text direction. Defaults to `'ltr'`; can be passed to `<UApp :dir>`.
  ::
::

## Localization

Component messages follow `<UApp :locale>`. English and Simplified Chinese are built in, with English as the fallback for other languages. Use `extendMovkLocale` to override the `movk` messages on a Nuxt UI locale:

```vue [app/app.vue]
<script setup lang="ts">
import { zh_cn } from '@nuxt/ui/locale'

const locale = extendMovkLocale(zh_cn, {
  searchForm: { search: 'Find' }
})
</script>

<template>
  <UApp :locale="locale">
    <NuxtPage />
  </UApp>
</template>
```

Use `useMovkLocale()` in custom components to read the same messages. Its `t('searchForm.search')` resolves the message for the current locale.
