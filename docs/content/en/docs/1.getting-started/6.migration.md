## Overview

v2 refocuses on schema-driven admin capabilities (AutoForm, SearchForm, DataTable, API) and removes components that overlap with Nuxt UI or offer little reuse value. This page lists every breaking change and its replacement.

## Removed Components

| Component | Replacement |
| --- | --- |
| `MWithClear` | Compose `UInput`, see the [Nuxt UI Input example](https://ui.nuxt.com/docs/components/input#with-clear-button) |
| `MWithCopy` | Compose `UInput`, see the [Nuxt UI Input example](https://ui.nuxt.com/docs/components/input#with-copy-button) |
| `MWithPasswordToggle` | Compose `UInput`, see the [Nuxt UI Input example](https://ui.nuxt.com/docs/components/input#with-password-toggle) |
| `MWithCharacterLimit` | Compose `UInput`, see the [Nuxt UI Input example](https://ui.nuxt.com/docs/components/input#with-character-limit) |
| `MWithFloatingLabel` | Compose `UInput`, see the [Nuxt UI Input example](https://ui.nuxt.com/docs/components/input#with-floating-label) |
| `MAsPhoneNumberInput` | Compose `UInput`, see the [Nuxt UI Input example](https://ui.nuxt.com/docs/components/input#as-a-phone-number-input) |
| `MPillGroup` | `URadioGroup` / `UCheckboxGroup` with `variant="card"`, or `UTabs` |
| `MColorChooser` | `UColorPicker` inside a `UPopover` |
| `MSlideVerify` | No built-in replacement; implement your own or use a third-party human verification service |
| `MPopconfirm` | Confirm buttons inside a `UPopover`, or the imperative [`useMessageBox`](/en/docs/components/message-box#usemessagebox) |

The `maska` and `colortranslator` dependencies are removed as well, along with the Props / Emits / Slots type exports of these components (such as `WithClearProps`, `PillGroupProps` and `ColorChooserProps`).

## Removed AutoForm Control Types

The following `type` values are no longer built in. Using them renders a `[AutoForm] No control mapped` notice:

- `withClear`, `withPasswordToggle`, `withCopy`, `withCharacterLimit`, `withFloatingLabel`, `asPhoneNumberInput`
- `colorChooser`, `slideVerify`, `pillGroup`

For simple cases, use `controlProps` on the default `UInput`:

```ts
const schema = afz.object({
  // Before: afz.string({ type: 'withPasswordToggle' })
  password: afz.string({ controlProps: { type: 'password' } }),
  // Before: afz.enum([...], { type: 'pillGroup' })
  category: afz.enum(['All', 'Frontend', 'Backend'], {
    type: 'radioGroup',
    controlProps: { orientation: 'horizontal' }
  })
})
```

For a reusable enhanced input, wrap it in a component inside your project and register it with `defineControl`. Keeping the original `type` name makes the migration seamless:

```ts
import PasswordInput from '~/components/PasswordInput.vue'

const { afz, controls } = useAutoForm({
  withPasswordToggle: defineControl({
    component: PasswordInput,
    controlProps: { class: 'w-full' }
  })
})
```

See [Controls](/en/docs/auto-form/controls#custom-controls) for details.

## Nuxt UI v5

v2 targets `@nuxt/ui` v5, which brings the following changes.

### Module Options

| v1 | v2 |
| --- | --- |
| `movk.theme.colors` | Removed, configure colors in CSS (see below) |
| `movk.theme.defaultVariants` | Removed, use `ui.defaultVariants` in `app.config.ts` |
| `movk.theme.prefix` | Defaults to `ui.tailwindPrefix` (formerly `ui.theme.prefix`) |
| `ui.experimental.componentDetection` | `ui.componentDetection`, enabled by default in v5 |

### Colors

The module no longer injects `blue` / `slate` and follows the Nuxt UI v5 defaults. Customize them in your CSS:

```css
@import "tailwindcss";
@import "@movk/nuxt";

@plugin "@nuxt/ui/colors" {
  primary: blue;
  neutral: slate;
}
```

`primary` / `neutral` of `useTheme` are `undefined` until a color is picked. Picking one writes `--ui-color-{primary,neutral}-*` on `<html>`, `exportCSS()` outputs the `@plugin` block above and `exportConfig()` no longer includes colors.

### Component Theme Overrides

Overrides move from `app.config.movk.<component>` to `app.config.ui.movk<Component>` and can be scoped with `<UTheme>`:

```ts [app.config.ts]
export default defineAppConfig({
  ui: {
    movkTree: { slots: { container: 'gap-4' } },
    movkDataTable: { slots: { toolbar: 'pb-4' } }
  }
})
```

| v1 | v2 |
| --- | --- |
| `movk.autoForm` | `ui.movkAutoForm` |
| `movk.searchForm` | `ui.movkSearchForm` |
| `movk.dataTable` | `ui.movkDataTable` |
| `movk.dataTablePagination` | `ui.movkDataTablePagination` |
| `movk.datePicker` | `ui.movkDatePicker` |
| `movk.messageBox` | `ui.movkMessageBox` |
| `movk.themePicker` | `ui.movkThemePicker` |
| `movk.tree` | `ui.movkTree` |

`app.config.movk.tv` and `app.config.movk.prefix` are removed, use `ui.tv` for the merge config. `app.config.movk` keeps theme options only: `radius`, `icons`, `blackAsPrimary` and `picker`.

### Other Changes

- `useDateFormatter` follows `<UApp :locale>` when `locale` is omitted and falls back to `'en'` outside components (was `'zh-CN'`).
- Clearing a range in `MDatePicker` emits `undefined` (was `{ start: undefined, end: undefined }`).
- The `tailwind-variants` dependency is removed.

## Documentation Paths

The docs are reorganized by capability. Old links redirect automatically:

- `/docs/composables/*` is split into the matching sections: `useAutoForm` → Forms, `useTheme` → Theme, `useMessageBox` / `useDateFormatter` → their component pages, upload/download and streaming → API
- The AutoForm field type pages are merged into [Field Types](/en/docs/auto-form/field-types), and `SearchForm` moves into the Forms section
- The three AI integration pages are merged into [AI Integration](/en/docs/getting-started/ai)
