## Overview

v2 refocuses on schema-driven admin features (AutoForm, SearchForm, DataTable and API) and removes components that overlap with Nuxt UI or offer little reuse value. This guide covers the behavior changes and replacements to check during the upgrade.

## Upgrade Steps

1. **Check runtime requirements.** Verify the supported versions, then update dependencies and the lockfile. See [Runtime and API](#runtime-and-api).
2. **Replace removed features.** Check the [component and type replacements](#removed-components) and [AutoForm controls](#removed-autoform-control-types).
3. **Review behavior changes.** Check [Forms, Table and Locale](#forms-table-and-locale) and the [API migration table](/en/docs/api#migrating-from-v1-to-v2).
4. **Verify the migration.** Run the project's lint, type checks, tests and build, then check the workflows your project uses.

## Migrate with AI

Open your coding assistant in the project root, then expand and copy the prompt or ask the assistant to read [the Markdown version of this page](/raw/en/docs/getting-started/migration.md). The prompt uses `v1.8.3` as its baseline and asks the assistant to check for earlier v1 changes when they apply.

## Removed Components

| Component | Replacement |
| --- | --- |
| `MWithClear` | Compose `UInput`, see the [Nuxt UI Input example](https://ui.nuxt.com/docs/components/input#with-clear-button) |
| `MWithCopy` | Compose `UInput`, see the [Nuxt UI Input example](https://ui.nuxt.com/docs/components/input#with-copy-button) |
| `MWithPasswordToggle` | Compose `UInput`, see the [Nuxt UI Input example](https://ui.nuxt.com/docs/components/input#with-password-toggle) |
| `MWithCharacterLimit` | Compose `UInput`, see the [Nuxt UI Input example](https://ui.nuxt.com/docs/components/input#with-character-limit) |
| `MWithFloatingLabel` | Compose `UInput`, see the [Nuxt UI Input example](https://ui.nuxt.com/docs/components/input#with-floating-label) |
| `MAsPhoneNumberInput` | Compose `UInput`, see the [Nuxt UI Input example](https://ui.nuxt.com/docs/components/input#as-a-phone-number-input) |
| `MPillGroup` | Choose `URadioGroup` / `UCheckboxGroup` with `variant="card"`, `UToggleGroup` or `UTabs` according to the interaction |
| `MColorChooser` | `UColorPicker` inside a `UPopover` |
| `MSlideVerify` | No built-in replacement; implement your own or use a third-party human verification service |
| `MPopconfirm` | Confirm buttons inside a `UPopover`, or the imperative [`useMessageBox`](/en/docs/components/message-box#usemessagebox) |

The `maska` and `colortranslator` dependencies are removed as well, along with the Props / Emits / Slots type exports of these components (such as `WithClearProps`, `PillGroupProps` and `ColorChooserProps`).

## Removed AutoForm Control Types

The following `type` values are no longer built in. Using them renders a `[AutoForm] No control mapped` notice:

- `withClear`, `withPasswordToggle`, `withCopy`, `withCharacterLimit`, `withFloatingLabel`, `asPhoneNumberInput`
- `colorChooser`, `slideVerify`, `pillGroup`

For simple cases, configure existing controls through `controlProps`. To retain an enhanced input, wrap it in a project component, register it with `defineControl` and pass `controls` to the form. A custom control can keep its original `type` name.

::code-group

```ts [Use built-in controls]
const schema = afz.object({
  // Before: afz.string({ type: 'withPasswordToggle' })
  password: afz.string({ controlProps: { type: 'password' } }),
  // Before: afz.enum([...], { type: 'pillGroup' })
  category: afz.enum(['All', 'Frontend', 'Backend'], {
    type: 'radioGroup',
    controlProps: { orientation: 'horizontal' }
  })
})
```

```ts [Register a custom control]
import PasswordInput from '~/components/PasswordInput.vue'

const { afz, controls } = useAutoForm({
  withPasswordToggle: defineControl({
    component: PasswordInput,
    controlProps: { class: 'w-full' }
  })
})
```

::

See [Controls](/en/docs/auto-form/controls#custom-controls) for details.

## Forms, Table and Locale

- **AutoForm binding.** Bind input state with `v-model` and type it with `z.input`. The old `:state` still works and emits a development deprecation warning.
- **Reset and clear.** `reset()` restores the baseline plus schema defaults. `clear()` keeps only schema defaults. Both update the bound object in place and emit a snapshot. Call `setBaseline()` after loading a record to make it the reset target.
- **SearchForm.** Bind expansion with `v-model:expanded`. Submit payloads trim strings and drop empty values by default. Set `:transform-payload="false"` to keep the original payload.
- **DataTable.** Action confirmations use `confirmLabel`, `cancelLabel`, `confirmButton` and `cancelButton`. Pagination uses complete templates with the keys `empty`, `total`, `range`, `rangeUnknown`, `selected` and `pageSize`.
- **Locale.** Component text and `useDateFormatter` follow the UApp locale with an English fallback. Set the UApp locale or pass a formatter locale when needed.
- **DatePicker.** `v-model:open` takes precedence over `popoverProps.open`. `popoverProps.defaultOpen` initializes uncontrolled state. Migrate existing controlled state to `v-model:open` before calling `open()` or `close()`.
